# LocalRush Android — design & screen brief (shared by all three apps)

Brand: primary orange `#F26B1D`, secondary charcoal `#23272F`, background `#F6F7F9`/white, success green `#16A34A`, cards radius 16–20 dp, Inter-style type, Material 3, light + dark. Smooth motion (Compose `animate*AsState`, shared element where cheap). Every screen: loading (shimmer), empty, error (retry), offline banner. No dummy buttons: every control calls a real API from `docs/API_CONTRACTS.md`.

## Customer app (`in.localrush.customer`) — reference: user screenshot "home"
1. **Splash** (animated logo) → **Onboarding/Welcome** (3 slides, skip) → **Location permission + pick delivery location** (map pin + "use current location" via `config/geocode/reverse`, search via `config/geocode/search`) → **Login/OTP** (guest browsing allowed: home/search/restaurant visible; cart/checkout prompt login) → terms/privacy acceptance.
2. **Home**: solid orange header with "Your Location ▾" (address line truncated) and bell icon (unread badge from `notifications/unread-count`); white rounded search bar "Are you hungry !!"; promo banners carousel (`home.banners`); "What's on Your Mind?" horizontal row of rounded-square category images (`home.categories`, tap → list filtered by category); peach "Find Nearby / Restaurant Near from You" banner with orange "See Location" button (opens map list); sections from `home.sections` (Nearby, Fast delivery, Popular, Top rated, Featured) as horizontal restaurant cards (cover, logo, name, ★ rating, time, fee, offer chip); "Recently ordered" and "Recommended for you" when logged in; cuisines row. Bottom nav: Home · Search · Orders · Profile; floating cart bar when cart non-empty.
3. **Search**: debounced `restaurants/search`, tabs Restaurants/Dishes/Cuisines, recent searches (local), filter sheet (veg, open now, rating, sort) → list via `restaurants/`.
4. **Restaurant details**: collapsing cover + logo, name, rating/reviews (sheet with `reviews/restaurant`), ETA, fee, min order, distance, hours, veg badge; menu grouped by category with sticky category chips; item sheet with variants (radio), add-ons (checkbox with min/max), quantity, special instructions, price updates live; add-to-cart handles `cart_restaurant_conflict` with a "Replace cart?" dialog.
5. **Cart**: items with ± quantity, customisations, instructions; coupon field + "View offers" sheet (`coupons/`), bill breakdown exactly from `pricing`, min-order warning, delivery address selector; **Checkout**: address list/add (map pin + form), delivery instructions, contactless toggle, payment methods (COD if `config.cod_enabled` and under limit; UPI/Card/NetBanking via Razorpay Checkout SDK `com.razorpay:checkout`), place order with idempotency key (UUID per checkout attempt) → for online: open Razorpay with the returned payload → `payments/verify/` → success screen; failure → retry via `payments/orders/{id}/retry/`.
6. **Orders**: Active / Past tabs; **Order detail**: items, bill, status timeline, cancel (if `can_cancel`), reorder, invoice (open HTML in Custom Tab / download), rate (stars for restaurant + rider + per-item), help → support ticket, refund status.
7. **Live tracking** (reference: tracking screenshot; this screen must be the showcase):
   - Top: `StepProgressBar` with stages Confirmed → Preparing → On the way → Delivered (green ticks, orange scooter icon on the active stage) derived from `timeline`.
   - MapLibre map (style from `config/`): restaurant pin, home pin with distance label, solid orange route polyline (`route.geometry`), custom scooter marker that **animates smoothly** between GPS fixes (interpolate position over ~3 s, rotate to `bearing`, ease), camera follows with padding and a "recenter" FAB, bounds fit on first load.
   - Bottom sheet: big orange ETA ("12 min", from `route.eta_at`/`estimated_delivery_at`, live-updated), order summary row, rider card (photo, name, ★ rating, deliveries, round Call and Chat buttons → `orders/{id}/rider-contact/` + chat screen over the tracking WebSocket), delivery OTP shown prominently once rider is on the way, order total row.
   - Data: `GET tracking/orders/{id}/` snapshot then `/ws/orders/{id}/tracking/` (reconnect with backoff; REST poll every 15 s as fallback while the socket is down); handle `rider.location`, `status.*`, `chat.message`.
8. **Profile**: edit profile, addresses, notifications list, help & support (FAQs, tickets, contact), about/legal, logout, delete account.
9. Push: FCM channels `localrush_orders`, `localrush_promos`; tapping opens the order/tracking screen (deep link `localrush://orders/{id}`).

## Rider app (`in.localrush.rider`)
1. Splash → OTP login → **Registration wizard** (personal details + photo, vehicle + licence, documents upload with camera/gallery, bank/UPI, emergency contact) → **Pending approval** screen (status from `riders/profile`, shows rejection reasons, allows resubmission).
2. **Dashboard**: big Online/Offline toggle (starts/stops the foreground location service; requires precise + background location with the Play-compliant prominent disclosure), today's deliveries & earnings, week/month, incentives progress, pending payout, current delivery card, rating.
3. **Offer screen** (full-screen, high-priority, with sound/vibration + countdown from `seconds_left`): restaurant → customer distance, payout, items; Accept / Reject (reason). Arrives via FCM `rider.offered` and `/ws/rider/`.
4. **Active delivery**: MapLibre navigation view — live GPS, restaurant/customer markers, route polyline, **turn-by-turn** instruction banner from `riders/orders/{id}/route/?lat&lng` (next maneuver + distance, voice via TextToSpeech optional), distance/ETA, recenter, re-route when off-route (>100 m); step buttons: Navigate → Arrived at restaurant → Enter pickup OTP → Picked up (auto "on the way") → Navigate to customer → Call / Chat → Arrived → Enter delivery OTP (+ optional photo proof) → Delivered → earnings toast. "Report a problem" sheet (customer unavailable, restaurant delay, vehicle issue, emergency) → support ticket.
5. **Background tracking**: foreground service with persistent notification; 3–5 s updates while on delivery, 15–30 s when online idle, pause when stationary; offline queue in Room; batch replay via `rider/location/` `{locations:[...]}` when back online; stop on offline/logout.
6. **Earnings**: today/week/month tabs, per-order list, incentives, COD cash in hand, payout request + history. **Orders history**, **Profile/documents**, **Support**.
7. Push channels `localrush_rider_offers` (custom sound), `localrush_rider_orders`.

## Partner app (`in.localrush.partner`)
1. Splash → login (OTP or password) → **Restaurant registration** (business, owner, address with map pin, logo/cover, FSSAI/GST/PAN, bank, hours, categories/cuisines, documents) → pending approval screen.
2. **Dashboard**: Open/Closed switch + "accepting orders", temporary closure; today's orders, revenue, completed/pending/cancelled, AOV, rating, best sellers, unsettled amount, last settlement.
3. **Orders** (real-time via `/ws/partner/` + FCM `localrush_partner_orders` with loud sound): tabs New / Preparing / Ready / Past; new-order card with timer since placed, items, customer note; Accept (set prep minutes) / Reject (reason); Preparing → Ready; rider card with arrival status and **pickup OTP** displayed large; order detail + history.
4. **Menu**: categories (add/edit/reorder/toggle), items list with search/filter, item editor (photo, name, description, price/discount, veg/non-veg, prep time, category, variants, add-ons, stock, availability toggle), bulk availability.
5. **Restaurant settings**: hours per weekday, holidays, min order, packaging charge, delivery radius, prep time, logo/cover, documents (status), profile.
6. **Finance**: summary with date range, order-wise lines, settlements list with status, download CSV statement (open/share). **Reviews** with reply. **Support**.
